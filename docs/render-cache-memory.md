# 2D 渲染缓存内存优化

日期：2026-11-05。实现范围：容量回收、2D 提取与相机过滤、HTML overflow、合成瓦片索引，以及文字绘制快照和字形记录。

## 容量与生命周期

复用 `internal/reuse.Retention` 的 30 次低使用量观察窗口。使用量持续不超过容量的四分之一时，保留近期峰值的两倍容量和小容量下限；完全空闲的大缓冲直接释放。相机和收集器的多批次调用记录本轮最大需求，避免最后一个小相机挤掉大相机的暖缓存。

回收覆盖 retained items、paint、damage、dirty 工作区、相机索引、收集器临时项、全局快照、实体空闲块、瓦片候选索引和 coverage。paint 搬迁后重新绑定 item 指针；实体池仅移除完全空闲的块，保留活跃节点地址。瓦片容量统计并入原有遍历，不增加每帧的实体扫描。

密集动态内容连续直接绘制 30 次后，释放旧 retained 场景。后续动态轮询只统计候选数量，避免重新分配已经退休的节点池；动态停止后重新建立 retained 缓存。

回收时允许一次容量调整分配；稳定的暖路径不分配。实体块不能移动，因此分散在多个块中的活跃节点仍会保留对应块。

## 删除与合并的数据

| 路径 | 实现 |
| --- | --- |
| 完整 2D 提取 | 直接写入最终 retained items，移除收集后再整数组复制的中间路径 |
| 相机过滤 | 保存 `uint32` 索引，通过泛型列表访问原始 item；批处理读取同一索引视图 |
| HTML overflow | box 拥有唯一 clip 记录，bindings、routes 和 entities 三个索引共享指针；滚动条 parts 复用容量 |
| 瓦片 | 候选和可见项共享一个 `[]uint32`，可见项是候选数组前缀；同一瓦片的旧 coverage 在首次修改时撤销 |
| 文字快照 | 只保存字形、图集和绘制参数；span 颜色已固化到绘制项，不再复制整份 Text2D 和编辑输入 |
| 字形缓存 | map 保存 `uint16` 槽位，CLOCK 数组集中拥有字形记录和淘汰键；维持 4,096 项总预算和弱图集引用 |

内联链接的 focus target 也从所属布局 box 获取 overflow 路由，使有无背景、完整更新和局部更新的裁剪行为一致。

## 结构大小与测量

Linux amd64、Go 1.27.3，结构大小不包含关联切片的底层存储或分配器开销：

| 数据 | 原来 | 现在 |
| --- | ---: | ---: |
| 每个相机过滤项 | 440 B | 4 B |
| 每个 overflow map 值 | 72 B | 8 B，共享一份 72 B 记录 |
| compositeTile2D | 80 B | 56 B |
| 文字绘制快照 | 640 B | 88 B |
| text.Glyph | 64 B | 48 B |
| textGlyph2D | 88 B | 72 B |

`Glyph` 的图集编号、坐标和尺寸改为 `int32`，`GlyphCache.Atlas` 接收同一类型；这是公开 Go API 的类型变化，调用方传入 `int` 变量时需要显式转换。

`TestRetainedRender2DReclaimsPeakStorage` 先创建 10,000 个实体，同时预热直接收集和相机过滤，再缩到 100 个实体并等待 64 帧。主要 CPU 缓冲由 **14,447,056 B 降至 178,872 B**，且保留活跃节点地址、paint 指针和稀疏重绘能力。这是同一实现中场景缩小前后的容量测量；不是进程 RSS 对照，也不包含 map、嵌套快照、合成瓦片或 GPU 存储。

## 验证

相关包完整测试通过：`internal/reuse`、`text`、`scene`、`ui/html`、`ui`、`html/layout`、`scene/render3d`、`render`、`graphics` 和根包。没有运行全仓 `go test ./...`，没有启动编辑器。

回归验证包括容量释放后稀疏重绘、活跃指针有效性、长时间直接绘制和恢复静态、过滤后的批次与空相机、嵌套 overflow 共享记录的更新和退休、瓦片随机编辑对照全量重建、字形淘汰槽位一致性和图集生命周期。稳定场景、稀疏更新、持续动态和缓存命中均保留零分配检查。

上述字形、容量回收、持续动态、索引批次和 overflow 回归的定向 race 检查通过。`fieldalignment` 检查相关四个包，无诊断。

最终单独绑定 CPU 2 运行基准，每项 300 ms、重复两次：10,000 项稳定帧约 1.59–1.63 μs，单项改色约 55.8–60.2 μs；HTML 全量复用约 21.4–22.4 μs，hover 复用约 28.9–31.8 μs。这些场景均为 **0 B/op、0 allocs/op**。渲染采用测试驱动，仅反映 CPU 工作；数字不作为 GPU 性能或相同条件下的优化前后对照。

复现容量测量：

```sh
go test ./scene -run '^TestRetainedRender2DReclaimsPeakStorage$' -count=1 -v
fieldalignment ./scene ./ui/html ./text ./internal/reuse
```
