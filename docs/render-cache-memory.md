# 渲染缓存内存优化

日期：2026-11-06。实现范围：容量回收、2D 提取与相机过滤、HTML overflow、合成瓦片索引、文字绘制快照和字形记录，以及嵌套快照、Spine、变换输出、3D 变形与跨视图共享、阴影 R8 存储。

## 容量与生命周期

复用 `internal/reuse.Retention` 的 30 次低使用量观察窗口。使用量持续不超过容量的四分之一时，保留近期峰值的两倍容量和小容量下限；完全空闲的大缓冲直接释放。相机和收集器的多批次调用记录本轮最大需求，避免最后一个小相机挤掉大相机的暖缓存。

回收覆盖 retained items、paint、damage、dirty 工作区、相机索引、收集器临时项、全局快照、实体池、瓦片候选索引和 coverage。本轮补齐层级队列与标记、纹理位置数组、3D 提取候选，以及存活实体内部的 sprite、文字、九宫格、粒子、瓦片和 Spine 快照数组。

实体提取时只把明显闲置的大缓冲加入延迟回收候选，后续帧仅检查这些候选。容量调整后按输出顺序重新绑定绘制引用，兼容同一次提取中数组增长产生的旧指针。paint 搬迁后也重新绑定 item 指针。实体池先移除空块；存活实体过于分散时搬迁节点并更新实体索引，绘制引用指向独立的快照数组，因此仍然有效。瓦片容量统计并入原有遍历，不增加每帧的实体扫描。

实体、纹理、HTML overflow 和 3D 几何索引 map 按历史最大项数估算容量，在持续低使用量后重建，释放 Go map 自身不会主动缩小的桶。

密集动态内容连续直接绘制 30 次后，释放旧 retained 场景。后续动态轮询只统计候选数量，避免重新分配已经退休的节点池；动态停止后重新建立 retained 缓存。

回收时允许一次容量调整分配；稳定的暖路径不分配。节点地址可能在碎片回收时变化，不对外提供地址稳定性保证；无需搬迁时保留现有节点。

## 删除与合并的数据

| 路径 | 实现 |
| --- | --- |
| 完整 2D 提取 | 直接写入最终 retained items，移除收集后再整数组复制的中间路径 |
| 相机过滤 | 保存 `uint32` 索引，通过泛型列表访问原始 item；批处理读取同一索引视图 |
| HTML overflow | box 拥有唯一 clip 记录，bindings、routes 和 entities 三个索引共享指针；滚动条 parts 复用容量 |
| 瓦片 | 候选和可见项共享一个 `[]uint32`，可见项是候选数组前缀；同一瓦片的旧 coverage 在首次修改时撤销 |
| 文字快照 | 只保存字形、图集和绘制参数；span 颜色已固化到绘制项，不再复制整份 Text2D 和编辑输入 |
| 字形缓存 | map 保存 `uint16` 槽位，CLOCK 数组集中拥有字形记录和淘汰键；维持 4,096 项总预算和弱图集引用 |
| Spine | 删除每个实例的 MeshBatch；几何生成时直接追加到共享批次并烘焙变换，省去第二次顶点和索引复制；裁剪回滚同时恢复前一个合并 draw |
| 普通／UI 变换 | 最终矩阵只保存在 ECS 输出组件，工作区保留局部矩阵及增量计算所需信息；递归解析时先提交父输出，再供子节点读取 |
| 3D 关节 | CPU 和 GPU 提交共享 `[]mgl32.Mat4`，删除每个 Deformation 的关节矩阵副本和转换循环 |
| 3D 几何索引 | CPU 动态几何位置与 GPU 变形编号合并为一个 map，允许同一 key 同时记录两种路径 |

内联链接的 focus target 也从所属布局 box 获取 overflow 路由，使有无背景、完整更新和局部更新的裁剪行为一致。

Linux amd64、Go 1.27.3，结构大小不包含关联切片的底层存储或分配器开销：

| 2D paint 记录 | 104 B | 40 B |
| 每个 overflow map 值 | 72 B | 8 B，共享一份 72 B 记录 |
| compositeTile2D | 80 B | 56 B |
| 文字绘制快照 | 640 B | 88 B |
| text.Glyph | 64 B | 48 B |
| textGlyph2D | 88 B | 32 B，本轮从 72 B 继续压缩 |
| 每个排版描边引用 | 48 B | 8 B |
| 3D 每视图提取项 | 560 B | 40 B，实体／子网格共享一份 544 B 载荷 |

`Glyph` 的图集编号、坐标和尺寸改为 `int32`，`GlyphCache.Atlas` 接收同一类型；这是公开 Go API 的类型变化，调用方传入 `int` 变量时需要显式转换。

`render.MeshDeformationData.JointMatrices` 从 `[][16]float32` 改为 `[]mgl32.Mat4`。调用方需使用统一的矩阵切片类型；提交期间借用其底层存储。

## 本轮：退休遗漏、阴影和共享载荷

opacity 分组恢复为普通节点时，在已有布局遍历中删除该分组拥有的 CPU 栅格及依赖记录。记录标明所属分组，退休时保留其他活动分组已经接管的子节点。回归场景中，旧分组的像素存储由 **105,536 B 降至 0 B**，另一个活动分组继续复用原图像，重新开启 opacity 后可以重建。

显式关闭 2D 合成缓存、视图退休或尺寸重建时，同时释放 retained、瓦片候选、coverage、damage 和槽位工作区。准备期间遇到暂时不支持的绘制项时，只释放 GPU 目标，复用 CPU 工作区；混合瓦片地图场景因此保持零分配。

阴影缓存保存 R8 覆盖率，RGB 通过 sprite tint 应用。透明度先写入覆盖率再模糊，保留旧实现的量化顺序；仅修改 RGB 可以复用纹理和 GPU 模糊结果。缓存键保存解析后的圆角与数值参数。小核 Gaussian 使用单通道行环形缓冲，大核使用三次滑动盒式滤波。CPU 输出在多组模糊、透明度、负 spread 和偏移条件下逐像素匹配测试中的旧 RGBA 参考实现。

渲染目标新增无深度附件的 `RenderTargetR8`，读回每像素一字节。GLES、Vulkan、WebGL2、WebGPU、Metal 和 DirectX 路径接入该格式；GPU 阴影的源、中间目标和最终目标均为 R8。每种格式共享一个文档级中间目标，通过现有退休遍历维护引用计数，在该格式的最后一个效果退出时释放。每个阴影像素载荷减少 **75%**；实际显存还受驱动对齐和分配粒度影响。

2D 绘制项以一个类型化载荷指针保存 sprite、文字、粒子等快照，自定义材质从公共项拆成可选的 72 B 记录。默认材质使用空指针，相邻相同自定义材质共享记录；容量压缩后重新绑定引用。设备从绘制上下文传入。paint 仅保存原始边界、哈希和标志，最终边界按绘制项计算。

3D 提取在任意相机或阴影视图实际需要实体时，捕获一次实体／子网格载荷。各视图独立保存距离和 CPU 顶点选择，共享材质、变换和已准备资源。主相机外的投射体仍参与阴影提取。一个子网格出现在 V 个视图时，提取记录从约 `560×V` B 变为 `544+40×V` B；该公式不包含切片容量、64 项存储块的尾部余量、几何和分配器开销。

排版字形保存 8 B 的 `GlyphRef`，共享不可变的 48 B 栅格描述，描边也使用同一机制。每个存活的唯一字形／描边描述分配一次；CLOCK 以弱引用查找描述，描述强持有图集页，槽位淘汰不会修改正在显示的文字，布局释放后图集页仍能回收。CLOCK 记录通过单独存储无页指针的度量数据保持 **80 B**。普通文字 N 个字符、U 个不同描述的存储约为 `32×N+48×U` B，原来是 `72×N` B；描边另占 `8×N+48×U_outline` B。收益取决于字符重复率。

本轮最新容量回归中，10,000 个实体缩到 100 个后，主要 CPU 缓冲由 **11,595,136 B 降至 111,960 B**。以下较早测量保留其原始测试时点。

本轮验证：`render`、`graphics`、`text`、`scene`、`scene/render3d`、`ui/html`、`ui`、`project` 完整包测试，以及着色器编译器定向测试通过。上述退休、共享引用、槽位淘汰和像素回归的定向 race 检查通过；Linux 六个相关包及 WebAssembly 渲染包的 `fieldalignment` 检查无诊断。没有运行全仓测试或启动编辑器。

Xvfb 下的 GLES 和 Vulkan 原生像素测试通过，覆盖 R8 读回、模糊、圆角挖空、方向、改色复用，以及 R8 工作区独立退休。DirectX 的 Windows 测试二进制交叉编译通过；WebAssembly 编译与 Node 下的 WebGL／WebGPU 定向测试通过。Metal 已接入，尚未实机运行。

通过指定 adb 地址连接到当前 Android arm64／API 35 设备，使用 NDK 27 编译并运行字形引用与页生命周期、2D 退休和材质压缩、窗口化文字、3D 多视图和相机外投射体、HTML 退休和 R8 CPU 像素回归，均通过。测试字体路径只在交叉编译时映射到设备目录。真实画面验收仍由人工完成。

本轮基准每项运行 200 ms：10,000 项稳定帧约 1.91 μs，单项改色约 63.6 μs，全量修改约 10.23 ms；1,000 个 3D 网格、两个相机约 1.15 ms；HTML 全量复用约 27.1 μs、hover 复用约 39.5 μs，均为 **0 B/op、0 allocs/op**。这些是测试驱动的当前 CPU 测量，运行时有其他验证进程，不作优化前后的性能对照。

`TestRetainedRender2DReclaimsPeakStorage` 先创建 10,000 个实体，同时预热直接收集和相机过滤，再缩到 100 个实体并等待 64 帧。主要 CPU 缓冲由 **14,447,056 B 降至 144,056 B**，保留有效的 paint 指针和稀疏重绘能力。这是同一实现中场景缩小前后的容量测量，不包含 map、嵌套快照、合成瓦片或 GPU 存储。

`TestRetainedNestedStorageShrinksWhileEntitySurvives` 将一个存活实体的 1,024 个 sprite layer、4,096 个粒子及相关颜色／外观记录、4,096 个瓦片各缩到 2 项。64 帧后，嵌套缓冲由 **592,088 B 降至 1,288 B**。`TestRetainedNodePoolCompactsScatteredSurvivors` 从 4,096 个实体中每 64 个保留一个，验证 64 个分散存活节点最终只占用 2 个块，绘制快照地址及稀疏修改仍有效。

另外用独立进程探针对比本轮修改前的 `dc85b7b` 和当前代码，每组运行三次：4,096 个实体缩到上述 64 个分散存活实体，同时缩小一个实体的嵌套内容，运行 96 帧后调用 `debug.FreeOSMemory`。探针创建场景带来的 `HeapAlloc` 增量从约 **5.31 MB 降到 3.39 MB，减少 36.1%**；`HeapInuse` 增量从 6.01–6.10 MB 降到 4.09–4.12 MB；Linux `RssAnon` 增量从 6.22–6.33 MB 降到 4.37–4.43 MB。这组数字包含 ECS、测试驱动和场景缓存，不代表完整应用 RSS 或 GPU 显存。源组件仍由 ECS 拥有，缩短源切片不会自动回收其底层数组。

## 验证

相关包完整测试通过：`internal/reuse`、`text`、`spine`、`scene`、`ui/html`、`ui`、`html/layout`、`scene/render3d`、`render`、`graphics`、`project` 和根包。没有运行全仓 `go test ./...`，没有启动编辑器。

回归验证包括容量释放后稀疏重绘、快照引用有效性、碎片化实体池压紧、长时间直接绘制和恢复静态、过滤后的批次与空相机、嵌套 overflow 共享记录的更新和退休、瓦片随机编辑对照全量重建、字形淘汰槽位一致性和图集生命周期。本轮还覆盖 Spine 变换、混合模式、裁剪回滚与容量回收，以及 3D 关节引用共享、CPU 零偏移索引与 GPU 变形共存、提取工作区回收。稳定场景、稀疏更新、持续动态和缓存命中均保留零分配检查。

上述字形、容量回收、持续动态、索引批次和 overflow 回归，以及本轮 map、嵌套存储、Spine、变换和几何共享的定向 race 检查通过。`CGO_ENABLED=0 fieldalignment` 检查本轮相关六个包，无诊断；禁用 CGO 是为了排除生成绑定代码的对齐诊断。`render` 包的 WebAssembly 测试二进制编译通过。

通过 `adb connect 10.0.0.174:16384` 连接 Android x86_64 设备，使用 NDK 27 编译测试二进制；设备上的 2D 容量回收、嵌套快照、碎片整理、Spine 合批、普通／UI 变换及 3D 共享关节和子网格定向测试通过。绘制使用测试驱动，GPU 显存测量和真实画面验收仍需独立进行。

最终绑定 CPU 2 运行基准，每项 300 ms、重复两次：10,000 项稳定帧约 1.57–1.61 μs，单项改色约 54.9–57.3 μs，全量修改约 8.52–11.49 ms；HTML 全量复用约 22.0–22.3 μs，hover 复用约 30.4–31.4 μs。这些场景均为 **0 B/op、0 allocs/op**。渲染采用测试驱动，仅反映 CPU 工作；数字不作为 GPU 性能或相同条件下的优化前后对照。
