# 引擎设计

[English](design.md) | [简体中文](design.zh-CN.md)

## 所有权与边界

- 应用主循环拥有 ECS 修改、任务调度与渲染。工作 goroutine 可以请求绘帧，
  但不能直接修改 ECS 状态。
- `World` 拥有组件存储、资源、变更 tick 和查询状态。结构修改通过 World API
  执行，并在查询借用存储期间延后；缓存的实体句柄必须校验实体生命周期和所有权。
- 模块拥有自身运行状态，并通过类型化消息、slot 和明确的生命周期阶段通信。
  场景拥有已准备好的场景内容。
- 窗口拥有自己的渲染设备和 Canvas。GPU 资源按设备保存驻留状态；带 CPU
  数据的资源可以先准备、后上传。没有导入器或 CPU 数据时，GPU-only 与外部
  资源不能在另一设备上重建。

## 调度与资源准备

默认持续更新。按需调度需要显式启用，所有依赖时间的工作都必须报告活跃状态
或安排截止时间。输入、显式绘帧请求、已跟踪的 ECS 修改和活跃效果会唤醒主循环。
CPU 资源准备可以在渲染线程之外进行；GPU 上传进入所属设备的队列，并受调用方
设置的上传预算限制。

## 渲染与 HTML

相机提取前同步变换。提取阶段确定稳定的绘制顺序，后续相机过滤和绘制应保留
该顺序。渲染 API 使用明确的窗口/设备上下文，不依赖进程级隐式设备。资源释放
通过所属驱动执行。

HTML 子系统将 DOM/布局状态与输出的 UI/渲染状态分开。局部修改应只更新受影响的
节点和祖先，同时保持文档顺序及浏览器行为。CSS 与 HTML 修改遵循 W3C 规则并与
Chromium 对照用例一致；不支持的行为应明确标出，不应静默近似实现。
